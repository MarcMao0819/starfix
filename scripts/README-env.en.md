# Environment variable list

**语言 / Language:** [中文](README-env.md) · [English](README-env.en.md)

The scripts keep **no absolute paths, no real IDs and no secrets**; everything is read from here.

There are two kinds, and they are used in completely different ways:

- **Required, no default** — if one is missing the script exits immediately and says which one.
  Withholding a default is deliberate: a default would make the script **silently read and write the wrong place**
  on someone else's machine, and an error is in fact the cheapest outcome (see the entry "only config with a default is dangerous" in `doctrine/02-试错战例集.en.md`).
- **Has a default** — it runs without being set, and every default lands under `$FLEET_HOME`.

---

## 1. Required

| Variable | Meaning | What happens if it is missing |
|---|---|---|
| `FLEET_HOME` | Fleet working directory: the activator json, the ask panel, snapshots and archives all live under it | Every script exits and prints "missing environment variable FLEET_HOME", exit code `1` (Python scripts) / `2` (relay) |

```bash
export FLEET_HOME="$HOME/fleet-data"     # the script creates the files itself if they are absent, but the directory must exist first
mkdir -p "$FLEET_HOME"
```

## 2. Paths (with defaults)

| Variable | Default | Where it is used |
|---|---|---|
| `ACTIVATOR_JSON` | `$FLEET_HOME/task-activator.json` | Data file of the task activator; point it at a copy when running tests, do not touch the real one |
| `FLEET_ASK_PANEL` | `$FLEET_HOME/请示台.md` | The ask panel generated by `task-activator.py` |
| `FLEET_ASK_INBOX` | `$FLEET_HOME/ask-inbox.jsonl` | Inbox of answers written back by the floating panel |
| `FLEET_DISPATCH_LOG` | `$FLEET_HOME/dispatch.log` | Dispatch log |
| `FLEET_WATCHDOG_TXT` | `$FLEET_HOME/watchdog.txt` | The session list the watchdog reads |
| `FLEET_SNAPSHOT` | `$FLEET_HOME/fleet-snapshot.txt` | The fleet snapshot from `fleet-scan.sh` (overwritten in place, always the latest) |
| `FLEET_SCRIPTS_DIR` | the directory the script itself is in | Working directory of `ask-inbox-apply.sh` |
| `FLEET_INTEGRATION_REPO` | empty | The git repo the integration branch lives in; if unset, the merge status check is skipped |
| `IM_ARCHIVE_DIR` | `$FLEET_HOME/im-archive` | Directory where IM conversation archives are written to disk |
| `FLEET_ACTIVATOR_JSON` | `$FLEET_HOME/task-activator.json` | The activator file read by the floating panel (Swift) |

## 3. IM relay

Recipients and app configuration are collected in one JSON, and **that file does not go into the repository**.

| Variable | Default | Note |
|---|---|---|
| `IM_CONTACTS_JSON` | `$FLEET_HOME/im-contacts.json` | App ID, secret source, recipient table, CC list; format in `examples/im-contacts.sample.json` |
| `IM_APP_ID` | takes `app_id` from the JSON | The environment variable wins |
| `IM_APP_SECRET` | takes `app_secret_file` → `app_secret` from the JSON | **Use the environment variable**; do not write the secret into the config file |
| `SECRETS_DIR` | none | In the sample, `app_secret_file` uses it to build the path; if unset you get "environment variable SECRETS_DIR is not set, the path cannot be expanded" |
| `PORT_IM_TUNNEL` | `8443` | The local SSH tunnel port to fall back to when the direct connection fails |
| `SSH_USER` / `HOST_LAN` | none | Only appear in comments, explaining how the tunnel is built; the scripts do not read them |

Secret precedence: the `IM_APP_SECRET` environment variable → `app_secret_file` in the JSON → `app_secret` in the JSON (plaintext, not recommended).

```bash
export IM_APP_SECRET="$(cat ~/.secrets/im-app-secret)"   # recommended
```

## 4. Behaviour switches

| Variable | Default | Note |
|---|---|---|
| `ACTIVATOR_STALL_H` | `6` | How many hours a task may go without a terminal state before it counts as "stalled"; the watchdog alerts on it |

## 5. Minimal runnable example

```bash
export FLEET_HOME="$HOME/fleet-data"
mkdir -p "$FLEET_HOME"

python3 scripts/task-activator.py add T1 "First task" --owner "Crew B"
python3 scripts/task-activator.py list
python3 scripts/task-activator.py report
```

The IM relay takes two more steps:

```bash
cp examples/im-contacts.sample.json "$FLEET_HOME/im-contacts.json"
# edit it: fill in the real app_id and the user ID of each role
export IM_APP_SECRET="..."
python3 scripts/relay/im-send.py Owner "test message"
```

## 6. How to confirm it is misconfigured

Every configuration error prints **one plain sentence + how to fix it**, never a Python stack trace. The scripts emit these messages in Chinese; they are shown here in English. The common ones:

```
missing environment variable FLEET_HOME (the fleet working directory). See scripts/README-env.md
configuration error: IM config file not found: /path/im-contacts.json
configuration error: the environment variable SECRETS_DIR in app_secret_file is not set, the path cannot be expanded: ${SECRETS_DIR}/im-app-secret
```

A stack trace means a real bug, not a missing setting — the two must be distinguishable at a glance.
