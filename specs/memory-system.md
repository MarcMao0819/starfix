# 记忆系统规范（Memory System）

**语言 / Language：** [中文](memory-system.md) · [English](memory-system.en.md)

舰长会被压缩、会换任、会同时开多个窗口。脑子里的不算记忆，文件里的才算。整套记忆分六层，每层回答一个不同的问题，混层是常见病（把项目事实写进方法论、把口径写进台账、把凭据写进任何一层）。

## 一、六层

| 层 | 文件 | 回答什么 | 自动加载 | 谁维护 |
|---|---|---|---|---|
| 1 索引 | `MEMORY.md` | 「有哪些记忆」——每条一行：标题 + 文件 + 一句钩子 | 是（每会话注入） | 舰长，写完事实文件后加一行 |
| 2 事实文件 | `memory/*.md`（frontmatter：`type: user / feedback / project / reference`） | 「某件事的结论 + Why + How to apply」 | 否（按索引召回） | 舰长 |
| 3 战略/方法论 | `doctrine/00–04` | 「怎么判断、怎么被考、工具怎么骗人」 | 上任第一动作必读 | 舰长（战例当天落） |
| 4 画像 | `crew/<代号>.md`、`people/<角色>.md` | 「这个 agent / 这个人是谁、擅长/口径/未结承诺」 | 派单/发消息前读 | 舰长（收单/对话后更新） |
| 5 台账与激活器 | `台账-*.md`、`task-activator.json`、`回执/` | 「今天做了什么、任务在哪、谁答了什么」 | 否（按需 grep） | 脚本 + 舰长 |
| 6 附属档 | `MEMORY-archive.md`、`MEMORY-optin-*.md`、模块索引 | 「低活跃/已上线/非本线的条目」 | **否**，Owner 明示才读 | 舰长（索引触顶时搬出，原文逐字保留） |

## 二、写入规则

- **一文件一事实**；写前先查有没有同题文件，有则更新不新建，错了的删。
- `feedback` 类必带 **Why** 与 **How to apply**；`project` 类把相对日期换成绝对日期。
- 不写仓库已记录的东西（代码结构、git 历史、CLAUDE.md）；Owner 要求记这类时，问「非显然的是什么」再记那个。
- **索引只放一行指针**，不放内容；索引触顶把低活跃条目整条搬进附属档，索引留一行「读存档档才读」。
- 人名角色化、项目名词最小化、**凭据永不入任何一层**（连「值已抹去」的痕迹都只留一句）。
- 每日日报单独一文件覆盖式更新（`daily_report_latest.md`），不进索引正文。

## 三、召回规则

- 会话开始：索引自动进上下文；上任第一动作读 doctrine 与最新战例 10 条。
- 做事前：按索引钩子召回相关事实文件；派单前读舰员画像；发消息前读对接人画像。
- 召回的记忆是「写时为真」：命中文件/函数/开关名要先验证还存在再引用。
- 附属档：Owner 说「读附属档/读存档」才读；「重新活跃」的条目搬回索引。

## 四、成长闭环

判断被推翻 / 侥幸蒙对 / 默认口径被改判 → 当天落 `02-试错战例集`（第一人称过程）→ 升华成规则进 skill（法条）→ 能变成门禁的变成门禁（「记得」不算记住，「跑一下会红」才算）。

## 五、脱敏与开源

- 本仓 `doctrine/` 是脱敏后的战略层样本；事实层、画像层、台账层**不进仓**（`.gitignore` 已排除运行时文件）。
- 分享任何一层前跑 `tools/scrub-gate.sh`。
