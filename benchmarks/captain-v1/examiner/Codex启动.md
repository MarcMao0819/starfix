# 原生 Codex 单候选考场

Astra 采用独立原生 Codex 客户端，固定 GPT-6 Astra、`high`。继续使用现有公开题面与四层确定性模拟器；真实舰员、真实 IM 与生产环境均不参与。本入口与 Grok 的运行平台不同，报告必须标明，不能把延迟差直接归为模型能力差。

## 准备与运行

将 `CANDIDATE_MODEL` 设为实际候选模型 ID（本轮为 GPT-6 Astra 对应 ID）。在本目录执行，使用原生可执行文件，不能使用会导入其他服务密钥的本机包装脚本：

```sh
python3 prepare_codex.py --out /tmp/captain-native-high-01 \
  --binary /path/to/native/codex --auth-home /path/to/codex-home --model "$CANDIDATE_MODEL"
python3 run_codex_exam.py --run /tmp/captain-native-high-01 --phase all
```

若本机访问供应商需要已有回环代理，可在准备命令加 `--proxy http://localhost:PORT`。代理仅用于该子进程，不改系统设置、其他客户端或全局配置。

准备过程只复制账户登录文件及模型目录到权限受限的独立 `CODEX_HOME`；不复制历史会话、记忆、用户配置、MCP、插件或工作区指令。运行目录必须在题库仓库外，不能重复使用已有路径。公开题包以白名单导出并校验哈希，考官文件留在独立目录。

## 隔离与运行证据

- 外层 macOS Seatbelt 禁止访问原用户目录、其他临时考场与本考场考官目录，并禁止启动除候选二进制和探针以外的进程。
- 正、反探针分别验证公开规则可读，以及考官清单、源评分锚点不可读。
- 关闭宿主执行、浏览、应用、记忆、技能发现、插件及协作功能；另外逐个禁用 CLI 自带技能。开考前检查实际组装上下文，发现额外技能或项目指令即中止。
- 每轮记录实际会话 ID，并从运行元数据核对模型与 effort；恢复时必须命中原会话，不能静默新开。
- 出现任何原生工具动作即拒绝将该轮输出送入模拟器。`tools=[]` 表示该轮未观察到原生工具动作，不宣称已拿到完整注册工具清单。供应商专用网络白名单也尚未实证；正式隔离认证保持未完成。
- `model_instructions_file` 使用统一公开舰长规则。CLI 自带的环境/协作元数据仍可能与 Grok 不同，属于 harness 差异。

每轮上限统一为 600 秒；不在看到表现后临时改变。此前 Grok 以 150 秒为主且有一次已记录的恢复，两者不能视为相同延迟预算。本入口未强制累计输出 token 上限，成绩属于预算未统一的校准记录。

模型自报 effort、客户端配置与实际运行元数据分别保存。实际运行元数据证明请求档位，不能证明内部推理工作量；自报未知是有效元数据，不扣分。不保存内部推理文本或原始诊断响应到评审产物，候选自身私有会话文件也不得发布到题库或报告档案。

L1、S08、S03、其余 L2、L3/L4 依序执行。跨轮反馈只含模拟器返回的公开结果。真正重建上下文时只传当前公开规则与候选自己留下的持久化入口，不传旧聊天、评分或建议。评分继续按冻结 `cases.json` 逐项人工审证后交给 `score.py` 计算。
