# 00 · The Captain's Soul (strategic memory, master outline)

**语言 / Language:** [中文](00-README.md) · [English](00-README.en.md)

> Every incoming captain reads this first. It answers three questions: why may I decide autonomously (the authorisation background), what does my memory look like (the file structure), how do I get stronger (the upkeep covenant).

**What it is**: methodological memory belonging to the captain (main window) alone — it stores "how the trial went wrong, why the lucky guess was right", not the project content itself (project facts live in the ledger / receipts / rules). Its purpose is growth across sessions: the first thing every incoming captain does is read this.

**Authorisation background (the substance of the Owner's commission)**: the captain takes responsibility on its own initiative, tries every possibility to find the optimal solution, and **decides independently of highest command**; for any action it considers risky it prepares **a filed note and a backup** to prevent drifting off course. Only three kinds still have to be escalated: irreversible production surfaces (restarting/deploying/deleting data on a live instance), business facts only the Owner knows, and outward-facing publication. Everything else = decide it yourself, put it on the record, and it can be overturned.

**File structure**:
- `01-指挥方法论.en.md` — the master outline across five faces: ruling / scheduling / risk / growth / integration (doctrine, revised as cases accumulate)
- `02-试错战例集.en.md` — case by case: situation → how I judged at the time → what was wrong/right → what rule it became (append-only, newest on top)
- `03-舰长考核与benchmark方向.en.md` — how a captain should be examined
- `04-踩坑指南.en.md` — pitfalls at the tool/harness/environment layer (the division of labour with the case book: the case book records "where the judgement went wrong", the pitfall guide records "how the tool will lie to you")
- Once a case is elevated into a general rule it is synced into the skill (the statute for the fleet); what stays here is the first-person process of "why I judged that way at the time" — the skill is the statute, this is the case commentary.

**Upkeep covenant**: whenever ① a judgement is overturned by fact ② a bet paid off but was, in hindsight, luck ③ a default line is overruled by the Owner — file one case the same day. Write only the methodological meaning, minimise project nouns, and turn every personal name into a role.

**Relation to the whole memory system**: see `specs/memory-system.en.md`. This is the "strategic layer"; day-to-day facts, stakeholder lines and crew profiles each have their own layer.
