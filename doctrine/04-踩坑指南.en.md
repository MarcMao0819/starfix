# 04 · Pitfall Guide (how the tools will lie to you)

**语言 / Language:** [中文](04-踩坑指南.md) · [English](04-踩坑指南.en.md)

> The division of labour with the case book: the case book records "where the judgement went wrong", this records "how the tool / harness / environment will give you a false signal". Every entry was actually stepped on. Project-specific pitfalls (a particular framework version, a particular port) are not collected; what is collected is what you will meet again on another project.

## 1. Shell and command line

- **The `grep` in an interactive shell may be a function wrapper** (ugrep and the like), behaving differently from the grep in a subprocess, which produces false negatives. Anything check-related uses `/usr/bin/grep` or python; before ruling "it does not exist", verify a second way.
- **The Bash tool may be zsh underneath**: an unquoted `$var` is not word-split; `PIPESTATUS` must be lowercase; a `$var` immediately followed by a full-width CJK character is absorbed into the variable name — always write `${var}`; globs such as `--include=*.java` must be quoted or `no matches found` exits outright.
- **Judge a build by the artifact's mtime, not by a piped echo returning exit 0**; in an `&&` chain, everything after the first red never ran, so confirm "all green" gate by gate.
- **A background job's exit code is the last command's**: the real failure (a 127, say) is written into the output file where nobody reads it. The criterion is the artifact line inside the output file.
- **Every path in the main window is explicitly absolute**: a persistent cwd can be carried off by another script, and relative paths go wrong in batches.
- **One double quote inside osascript content makes the whole thing fail silently** (-2740) with no error; always escape external content before it enters osascript; verify with a counterexample that would blow up the old version.
- **Never use a loose `pkill` match to stop your own service** (it hits same-named processes); go by PID.
- **Passwords never go in argv** (`ps` can see them): use an environment variable or a one-time account.

## 2. False signals from gates and tests

- **Type checking exiting 0 does not mean it checked**: some entry points only do syntax, not types; an incremental cache destroys the baseline comparison; the bar chart from `git apply --stat` scales with terminal width, so use `--numstat`.
- **The evidence that a gate is green is the characteristic line, not the exit code**; "ERROR=0" against an empty log is a false green — the three-part smoke kit = health 200 + `Started` line = 1 + ERROR = 0.
- **"I changed it and the run is green" does not prove the assertion works**: a newly written assertion must go through a satisfiability experiment (deliberately inject the degradation it claims to stop → it must go red).
- **A mock's default return value will fool a business branch** (a wrapper type returning 0 is not null); a newly added method must be stubbed explicitly.
- **An HTTP status code cannot judge "the route is not registered"** (a business rejection is also a 200, and a 401 cannot judge absence either); look at the shape of the response body.
- **A switch that is not explicitly forced false still takes effect from the config file**: not passing the flag on the command line ≠ off; suppress every key of the default matrix explicitly, otherwise four identical results mean the four configurations were actually one.
- **Attributing pre-existing reds requires a run in the same environment over the same scope on each side, with the totals quoted**; unequal totals = you are not comparing the same set.
- **A result file overwritten under the same name erases the most informative run** (the first-round FAIL overwritten by later ones); give result files a round suffix or use append mode; a claim of "I kept the failure record" must first confirm that path really writes to disk (the abort branch is often written before the write).
- **A self-proof method must pass its own criterion**: would the experiment that "proves X holds" go red when X does not hold? If it cannot go red, it is a tautological criterion.
- **The two diseases of a criterion are mirror images**: always green / red on day one for no good reason. When the output is constant, suspect a broken path first.

## 3. Line endings, patches and commits

- **Bulk file edits must preserve line endings**: read and write with `newline=''`; the CR count after = the CR count before + the CRLF lines added/removed this time (look at the delta, not the absolute value); a pure line-ending change is judged AMBIGUOUS, not PASS.
- **A patch script that raises halfway loses the first N steps**: write to disk step by step, and grep to verify each step afterwards.
- **In a shared worktree, merge-base degenerates into HEAD compared with itself and is always empty**: assert `base != head` in the baseline.
- **A `git commit` type tool may sweep the whole index in**: force explicit paths; after committing, self-check the scope with `diff --cached --stat`.
- **Before registering a branch that contains a merge, check where the first-parent chain lands**: it may land on the old integration head.
- **After resolving conflicts you must compile before landing the merge commit**: when complementary conflicts share context lines, "keep both sides" splices the structure into something broken.
- **Several parallel tasks all inserting a section at the top of the same document**: any movement of the integration head is a conflict; the conflict-resolution script must fail hard.

## 4. Processes, deployment and databases

- **Swapping a jar: stop first, then swap**: overwriting the running jar before TERM lets the old JVM lazily load classes from the new jar as it shuts down; graceful shutdown fails and you are left with -9.
- **A shared process is never started from `target/`**: repackaging breaks the running JVM; a resident process uses only a copy under `run/`.
- **Starting a service by hand with credentials not injected raises no error**: you find out after a round of FAILED pulls; both the start script and the by-hand line must first do `set -a; . env; set +a`.
- **It is the config with a default that is dangerous**: a missing data source / CORS / port / gateway address silently connects to production; root variables like `FLEET_HOME` are required with no default.
- **A variable inside a trigger that shadows a column** reads NULL; always prefix variables; for a 503 with zero logs, find it with general_log.
- **A trigger's INSERT/UPDATE criteria must be symmetric on both faces**, sharing a stored procedure, with the negative case fired at both.
- **Comparing strings across tables with mixed collations is a hard error** (1267); use an explicit COLLATE plus a functional test.
- **Reverse-proxy headers do not inherit across levels**: one directive of the same name inside a location kills every same-named header at the server level, with no warning.
- **A missing business API prefix gets silently swallowed by the SPA fallback into a 200 + index.html**.
- **When disk runs low, check the database binlog first**: with retention not shortened, a few days is hundreds of GB; clear it only with the database's own commands (PURGE + set an expiry), never touching the container or data directory.
- **If the container's memory ceiling is low, do not start a second JVM inside it**: the OOM 137 kills the database.

## 5. Multi-agent collaboration

- **The delivery keyword must be a literal substring of the message body**, otherwise the read-back never matches and the same task queues up over and over; session IDs are copied from the list file only.
- **On `UNCONFIRMED`, read the screen first to see whether it is already queued; do not resend.**
- **An append-only shared file must never be rewritten in place** (`tail -F` replays the entire history); stop the monitors before scrubbing.
- **A sub-agent's write operations carry the sub-agent's identity**: a subsequent commit from the main session may be stopped by an ownership guard; the main session takes ownership back by writing once itself.
- **A sub-agent inherits the session's model by default**: "I dispatched model X" is not a fact — specify it explicitly and check afterwards.
- **Garbled Chinese on paste is a known terminal phenomenon**, the bytes are correct, do not fix it.
- **A monitor's criterion must also be tested for discriminability**: if the `tail -3` sampling window cannot cover the newline, it matches the old line forever.
- **Every "fact" in a task book must be `ls`'d or `head`'d**: a path written from memory, an "old draft" judged from memory, costs more than a wrong instruction; for an either/or instruction, spell out both branches.
- **Scrubbing rules written by "what the name looks like" will miss "part of a name, and its variants"** (a surname with an honorific; `\bName\b` has no word boundary against CJK; a hyphenated token compared as a whole slips past the word list); the replacement count is not the criterion — spot-checking the real output is.

## 6. Frontend and interface

- **A UI library's API has a similar name but silently drops the event** (writing row-selection the way another vendor does); click a new interaction for real, headless.
- **Rendering external HTML in an `iframe sandbox` requires all four tokens**.
- **A regex replacement must not cut block-level tags in half**: a broken tag cascades into a whole-page failure.
- **A spread binding and a slot must belong to the same node** (judged by AST, checked both ways).
- **When reworking several pages of the same type, click every interaction entry point on every page for real**; grep symmetrically on both the desktop and mobile sides.
- **Controller gating and module-code gating must come from the same source**: putting the gate only on the controller gives a dead entry point where the route 404s while the menu is still visible.

## 7. Meta-lessons

- **Do not remember a conditional rule as an unconditional one**: before citing any existing rule, answer "what are its preconditions, and does this scenario satisfy them".
- **Automation is not immunity**: a script built precisely to cure hand-written expiry dates was itself caught by a precondition pitfall; the cure = an absolute baseline + a self-protecting assertion before writing the file + an idempotency self-proof.
- **Define the sweep boundary by the failure surface, not by the lead**; closure does not rest on anyone remembering, it rests on a machine-readable table.
- **Every column of a checklist handed to someone else to execute must have a source verified on the spot**, with unverified items individually marked.
