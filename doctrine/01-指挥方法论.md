# 01 · 指挥方法论（doctrine，随战例修订）

**语言 / Language：** [中文](01-指挥方法论.md) · [English](01-指挥方法论.en.md)

> 遇事不决回这里；这里也不决，就按「可逆优先+留痕」现场裁，事后落战例。

## 一、裁决面（怎么做决定）

1. **默认口径先走，裁定进可推翻清单**。等拍板是最贵的等待；错裁定比不裁定便宜——只要①留痕②可逆③最高指挥随时可改判。真正要停下问的只有三类：不可逆生产面、只有人类知道的业务事实、对外发布。
2. **裁决依据按序取**：红线原文 > 已有裁定先例 > 体系文件/代码实物 > 我的推断。跳级要在裁决里写明"此处是推断"。
3. **两个下游给出相反事实时，默认解释是锚点时间差不是有人错**——先查各自锚点实物再裁；查实前不采信任何一方。
4. **对"该不该做"拿不准时，把问题变成"做了怎么撤"**：能一条命令撤干净的直接做；撤不干净的先备份再做；备份不了的才上升。
5. **别人递来的清单/回执/记忆都不是事实，实物才是**。收到即抽查：一条命令能验的当场验（今天回执名对账漏了 <日期> 已建的代码，代码考古当场推翻了我的"从未施工"）。

## 二、调度面（怎么用舰队）

1. **回执是唯一事实源**；窗口自报、总线消息、我的印象都不算。状态变化必须变成文件。
2. **双模型结对**：承建→另一模型互审；返工优先原承建，复审优先原审官（判词就是验收基准）；利益冲突自报即换人。
3. **同一分支只许一个工位在写**（串行返工）；复审一律 detached 钉锚点，后续追加不算违例但审的区间不许动。
4. **任务书 token 经济**：上下文直接贴、白名单≤5、验证命令唯一化；收尾条款逐字带；按所在终端选通道两步+读回，同 harness 用总线，判据=消息进历史区。
5. **窗口一空就派，队列永远备着下一单任务书**；等待器（一次性 idle 通知）比轮询省，事件驱动比巡场稳。
6. **每单收官必做三件**：确认收尾干净（端口/库/账号清零）、滚更台账+哨兵名单、好教训当场入 SKILL/战例——过夜就丢。

## 三、风险面（怎么不翻车）

1. **风险动作三件套：备份→动手→自证**。改共享物先记录原状（git 原 HEAD、文件字节数、DB SELECT 快照）；恢复类操作先定性"哪一版是对的"再动（HEAD 版不一定对）。
2. **合并=主窗亲手做**：锚点钉双审 PASS 的 sha 不追分支头；解冲突默认并集保双方，语义冲突看懂两边意图再并；解完必过编译；波收口跑门（前端两道+专项契约+菜单三门禁+默认门）。跨线组合红（各自批内绿、合并红）恰是波门的意义，逐案定性别急着当谁的错。
3. **判据没有判别力=没有判据**。签发任何"绿"之前问：它红过吗？拿改动前版本跑会红吗？自检是闸还是报告？
4. **投递宁可不投，不可误发**；读回取样窗口要罩住换行（自己立的规矩自己最容易栽）。
5. **额度、断流、停工、回执四路监控常挂**；监控自身的判据也要验判别力（tail -3 之祸）。

## 四、成长面（怎么变强）

1. 判断被推翻→当天落战例；侥幸蒙对→也落（侥幸不识别，下次就是事故）。
2. 战例升华为规则进 SKILL（舰队法条）；这里留第一人称过程（判例评注）。
3. 接手/压缩后第一件事：读 00-README + 本文 + 战例集最新 10 条。

## 五、集成与批处理面（<日期>～<日期> 战例 30–41 沉淀，Owner <日期> 令写入）

1. **外部系统的枚举先看真回包再写映射**。<外部ERP>「已关闭」传的是编码 B 不是中文字；靠显示文本映射的代码在真数据上一张都认不出（战例 40），反过来把认不出的当作废就是事故（战例 41）。任务书必须要求「用真实回包列出实际值域并逐值给映射」；mock 通过不算通过。
2. **缺省分支只准落安全侧**。「未知状态→待人工/只记事件」是安全侧；「未知状态→作废/取消/完成」是危险侧（守卫失效方向，见 [[feedback-guard-failure-direction]]）。任何会自动改单据状态的回流路径，首次上线先跑一轮观察模式（只记事件不动数据），主窗核事件计数后才放开；上线次日早上必查「事件表按类型计数 + 取消/作废单增量」。
3. **批处理接口五件套，缺一不并线**：有界入口（limit/指定 ID）、分批事务（每批提交+run 留痕）、每批 INFO 日志、后台执行立即返回 runId 且 /status 可查进度、网络调用不在事务内。上线第一步只跑 ≤3 条真数据看落库，再全量。主窗对无进度信号的长任务最多等 30 分钟，超时停下补观测手段，不是继续等（7h20m 零落库，战例 40）。
4. **「并线≠上线，上线≠可用」**。判断项目状态的单位是模块里的每张单据，不是单子（Owner <日期> 纠偏，[[feedback-inventory-by-document-six-cells]]）：后端/前端/字段关联/单据关联/数据现状/完成度五档六格齐才算盘过。任务-回执视角只能看出派过什么，看不出能不能走通。
5. **转述别人的修改建议前先 grep 出现点**。把审官的「新增独立变量」压成「改名」派了出去（战例 39）——凡是改名/合并/删除类指令，符号出现点 >1 处就不能凭印象写；要么自己核，要么原文引用并标「以其为准」。被纠正立刻覆盖投递并令回退。
6. **判据与实物同口径、规程不许两句打架**。判据用「枚举」写而实物按「来源」算，审官白跑一轮（战例 34）；同一规程两句相反，两窗各按一句做出相反的事（战例 35）。写判据先看实物字段怎么算的；规程冲突当场合并成一句再派。
7. **记忆里的坑必须变成门禁才算记住**。双构造函数缺 @Autowired 记忆里有、原样复发（战例 36）→ Spring 装配冒烟成硬判据。原则：靠「记得」的坑迟早复发，靠「跑一下就红」的坑才不复发。
8. **部署窗的开关写进错命名空间等于没开**（战例 32）：新键先跑孤儿键检查（键路径回溯到消费者），闸开没开用探针看 body 不看 401；部署后钉前端到同一锚，停旧进程轮询到端口释放，超时才 -9。
9. **共享进程不从 target/ 起**（战例 30）：重打 jar 会打坏运行中的 JVM；一切常驻进程只用 run/ 副本 + 立即返回的启动脚本（PPID=1）。
10. **「查不到 ≠ 没发生」不能升级成实害上报**（战例 38）：上报实害要两条独立证据；一条查询空结果只能写「未见」。反过来，对员工和 Owner 的口头结论也一样——先秒回收到，再查实再答（[[feedback-employee-msg-ack-first]]）。
11. **只读审官的终态之外还要读「发现」**（战例 31）：生产预告漏项常藏在非阻断发现里；并线前把非阻断项逐条裁定（收编/小单/备案），不让它们随波消失。
12. **文档顶部并发冲突是常态**：多单并行都往 implementation-plan 顶部插段，复审期集成头一动就 rc=1。处置在候选工位合入现头两段并存；解冲突脚本必须 fail-hard，别把 add/commit 用换行接在断言后面（第一次就把冲突标记提交了）。

### <日期> 补：清点与闭合
- **清点边界按失效面定义，不按线索定义**：顺着一个参数/一个关键词找完就宣布清点完成，必漏（HPURGE 一审 FAIL 实例）。先问「哪些东西会连上/写到不该碰的地方」，再列全所有能到达那里的路径。
- **闭合不靠人记得，靠机器读的表**：白名单/清点表入仓、门读表、表外命中红、表内过期行也红（只进不出的白名单不是判据）。
- **规矩一立同时写判定范围**：否则承建把他域命中当自家 FAIL（RELCLOSE 增补1），或把范围外当免检。
- **存证/零变化类动作也要非空判据**（<日期> ZOMBIE）：删库前的结构快照因 zsh 不分词导出了 16 行空壳，是「快照必须含 CREATE TABLE」这条判据当场照出来的；否则会带着假快照去做不可逆动作。任何「备份完了」「导出完了」都要答得出「什么情况下它会红」。
- **串联守卫：退出码对了不等于是这道判据拦的**（<日期> HPURGE 增补3）：多道守卫串联时，反例必须验「拒绝理由来自被测守卫」，否则假绿；「还原必红」工序是把这类假绿照出来的唯一手段，不能省。

- **判据的两种病（<日期> 舰员癸）**：永远绿（无判别力）与上线即红且红得没道理（历史数据被算进去）——看似相反，代价相同：那条判据从此没人当真。写判据先问「什么情况下它会红」，再问「现状它为什么不红/为什么红」，两个答案都要说得出口才上线。
- **恒定观测量不给信息（<日期> 舰员癸三例）**：漂移清除恒不清、心跳 cycle 恒累加、rerouted 恒 0——恒在哪个值上都不区分「世界很干净」和「通路断了」。每个观测量上线前问「它凭什么会变」，并把「沙箱里证明有判别力」与「生产上证明接对了地方」分开记，不把前者读成后者。
