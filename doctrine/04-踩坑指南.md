# 04 · 踩坑指南（工具会怎么骗你）

**语言 / Language：** [中文](04-踩坑指南.md) · [English](04-踩坑指南.en.md)

> 与战例集分工：战例集记「判断错在哪」，这里记「工具/harness/环境会怎么给假信号」。每条都是真踩过的。项目专有的坑（特定框架版本、特定端口）不收；收的是换个项目还会遇到的。

## 一、Shell 与命令行

- **交互 shell 的 `grep` 可能是函数包装**（ugrep 等），与子进程里的 grep 行为不一致，会假阴性。检查类一律 `/usr/bin/grep` 或 python；判「不存在」前必第二路复验。
- **Bash 工具底层可能是 zsh**：未加引号的 `$var` 不分词；`PIPESTATUS` 要小写；`$var` 紧跟中文全角字符会并进变量名——一律 `${var}`；`--include=*.java` 这类通配要加引号否则 `no matches found` 直接退出。
- **构建成败看产物 mtime，不信管道 echo 的 exit 0**；`&&` 串联第一道红了后面等于没跑，判「全绿」逐道确认。
- **后台任务的退出码是最后一条命令的**：真正的失败（如 127）写在输出文件里没人读。判据=输出文件里的产物行。
- **主窗一切路径显式绝对**：持久 cwd 会被别的脚本带走，相对路径整批错位。
- **osascript 内容含一个双引号就整条静默失败**（-2740）且不报错；外部内容进 osascript 前一律转义；验证要用会炸旧版的反例。
- **停自己的服务禁 `pkill` 粗匹配**（误伤同名进程）；按 PID。
- **口令禁入 argv**（`ps` 可见）：走环境变量或一次性账号。

## 二、门禁与测试的假信号

- **类型检查 exit 0 不等于检查了**：某些入口只做语法不做类型；增量缓存会毁基线对照；`git apply --stat` 的条形图随终端宽度变，要用 `--numstat`。
- **门禁绿的凭据是特征行，不是 exit code**；空日志的「ERROR=0」是假绿——冒烟三件套 = 健康 200 + `Started` 行 = 1 + ERROR = 0。
- **「改完跑一遍绿」不证明断言有效**：新写的断言必须做可满足性实验（人为注入它声称要拦的退化→必须立红）。
- **Mock 的默认返回值会骗业务分支**（包装类型返回 0 不是 null）；新增方法必须显式打桩。
- **HTTP 状态码判不了「路由没注册」**（业务拒绝也是 200，401 也判不了缺失）；看响应体形状。
- **不显式压 false 的开关仍从配置文件生效**：命令行不传参≠关闭；默认态矩阵逐键显式压制，否则四行结果相同=四种配置其实是同一种。
- **存量红归因必须同环境同范围各跑一遍并贴总数**；总数不一致=比的不是同一批。
- **结果文件同名覆盖会抹掉信息量最高的那次**（首轮 FAIL 被后续覆盖）；结果文件带轮次后缀或追加模式；「我保留了失败记录」的主张先确认那条路径真的会写盘（中止分支常写在落盘之前）。
- **自证方法要过它自己的判据**：「证明 X 成立」的实验在 X 不成立时会不会红？红不了是恒真判据。
- **判据两种病是镜像**：永远绿 / 上线就红得没道理。输出恒定先怀疑通路断了。

## 三、行尾、补丁与提交

- **批量改文件必须保行尾**：读写带 `newline=''`；改后 CR 数 = 改前 CR 数 + 本次增删的 CRLF 行数（看差值不看绝对值）；纯行尾改动判 AMBIGUOUS 不判 PASS。
- **补丁脚本中途 raise 会丢前 N 步**：分步落盘，事后 grep 核验每步。
- **merge-base 在共享工作树里会退化成 HEAD 自比恒空**：基线断言 `base != head`。
- **`git commit` 类工具可能把整个索引扫进去**：强制显式路径；提交后 `diff --cached --stat` 自检范围。
- **带 merge 的分支登记前先核第一父链落点**：可能落到旧集成头。
- **解冲突后必须编译再落合并提交**：互补型冲突共享上下文行时「保双方」会拼坏结构。
- **多单并行都往同一文档顶部插段**：集成头一动就冲突；解冲突脚本必须 fail-hard。

## 四、进程、部署与数据库

- **换 jar 先停后换**：先覆盖运行中的 jar 再 TERM，旧 JVM 关机时懒加载到新 jar 的类，优雅停机失败只能 -9。
- **共享进程不从 `target/` 起**：重打包会打坏运行中的 JVM；常驻进程只用 `run/` 副本。
- **手工起服漏注入凭据不报错**：拉取一轮轮 FAILED 才发现；起服脚本与手工行都必须先 `set -a; . env; set +a`。
- **有缺省值的配置才危险**：数据源/CORS/端口/网关地址漏配即静默连生产；`FLEET_HOME` 类根变量必填无默认。
- **触发器里同名变量遮蔽列**读到 NULL；变量一律前缀；503 零日志用 general_log 找。
- **触发器 INSERT/UPDATE 两面判据要对称**，共用存储过程，负例两面打。
- **跨表比串遇排序规则混用是硬错**（1267）；显式 COLLATE + 功能实测。
- **反代 header 不跨层继承**：location 里出现一条同名指令，server 层同名头全失效且无告警。
- **业务 API 前缀漏了会被 SPA fallback 静默吞成 200 + index.html**。
- **磁盘告急先查数据库 binlog**：保留期没设短，几天就是几百 GB；只用数据库自身命令清（PURGE + 设过期），不碰容器/数据目录。
- **容器内存上限小就别在里面起第二个 JVM**：OOM 137 杀的是数据库。

## 五、多代理协同

- **投递关键词必须是正文字面子串**，否则读回永不命中、同一单反复排队；会话 ID 只从清单文件复制。
- **`UNCONFIRMED` 先读屏核是否已排队，勿重发**。
- **只追加的共享文件禁原地改写**（`tail -F` 会重放全部历史）；脱敏前先停监听。
- **子代理的写操作带子代理身份**，主会话后续提交可能被 ownership 守卫拦；主会话自己写一次夺回。
- **子代理默认继承会话模型**：派「某模型」不是事实，显式指定并事后核对。
- **粘贴中文乱码是终端已知现象**，字节正确，不修。
- **监听的判据也要验判别力**：`tail -3` 取样窗罩不住换行就永远命中旧行。
- **任务书里的「事实」每条要 ls/head 过**：凭印象写的路径、凭印象判的「旧稿」，比指令错更贵；二选一指令把两个分支都写清。
- **脱敏规则按「名字长什么样」写会漏「名字的一部分和变形」**（姓氏敬称、`\bName\b` 遇 CJK 无词边界、连字符 token 整体比对绕过词表）；替换计数不是判据，抽查真实输出才是。

## 六、前端与界面

- **UI 库 API 名字像但事件静默丢**（照另一家写法写 row-selection）；新交互 headless 真点。
- **`iframe sandbox` 渲染外部 HTML 必须四个 token 完整**。
- **正则替换不得切碎块级标签**：破碎 tag 连锁整页故障。
- **展开绑定与插槽必须归属同一节点**（AST 判，双向查）。
- **同型多页改造每页每个交互入口独立真点**；桌面/移动两边 grep 对称。
- **控制器门控与模块码门控必须同源**：只给控制器挂闸=路由 404 而菜单仍见的死入口。

## 七、元教训

- **条件规则勿记成无条件规则**：引用任何既有规矩先答「它的成立前提是什么、本场景满足吗」。
- **自动化不等于免疫**：为根治手写数字过期而生的脚本，自己就栽在前提坑上；修法=绝对基线 + 写文件前的自保断言 + 幂等自证。
- **清点边界按失效面定义，不按线索定义**；闭合不靠人记得，靠机器读的表。
- **交付给他人执行的清单每一栏都要有当场查证的来源**，未查证项逐项标注。
