# 轨迹编译（Trajectory Compiler）· 逻辑与原理

**语言 / Language：** [中文](trajectory.md) · [English](trajectory.en.md)

![轨迹编译](img/06-trajectory.svg)

## 一、它解决什么

舰队每天产生几十份回执、登记、并线、部署。舰长逐份人工核对不现实，全交给模型审又会「永远绿」。轨迹编译的做法：**把人（或模型）审一张单时走过的每一步记成轨迹，把稳定的步骤编译成机器可复放的图，只把不稳定的分支留给模型。**

## 二、三个部件

| 部件 | 输入 | 输出 | 关键规则 |
|---|---|---|---|
| 归纳器 `inducer/` | 历史审计轨迹（每步 `kind=sql/git/compare`，每步必须输出 `verdict=`） | 工作流图 `graphs/<flow>.vN.json`：节点（seq、kind、branch）+ 判决规则 `verdict_rules`（p1…） | 每个判点记「稳定度」：10 轮观测 10/10 一致且无反例 → `mechanical`（不需模型）；否则 `llm`（异常分支才交模型，并附上下文） |
| 运行器 `runner/run_graph.py` | 图 + 一张新单（登记号 / 部署 / 路由） | 逐节点执行，机械判点直接出 verdict，异常分支路由给模型 | 判点顺序固定（p1..p5）避免行为漂移；同一 run 内同一分诊标签 |
| 轮询器 `runner/audit-poller.sh` | 每分钟扫新登记、版本真相、路由 | 告警落盘到回执目录 + 心跳（pid/started） | 告警带处置段；漂移告警按祖先判据自清（head 已在 LIVE 中）；未处置告警每拍重评路由（B 门） |

## 三、七个判点（changeset-audit 图）

| 判点 | 查什么 | 会红的情形 |
|---|---|---|
| p1 | 登记里的提交哈希格式合法且在仓库里存在 | 手写/截断的哈希、未推的提交 |
| p2 | 三方文件数一致：登记表 / 文件明细表 / `git diff` | 登记漏文件、多登记 |
| p3 | 文件路径清单 DB 侧 = git 侧（逐行 diff） | 路径改名未同步、夹带文件 |
| p4 | 标题无 GBK/UTF-8 错解码乱码 | 终端粘贴乱码进库 |
| p5 | 行尾双规则：新增文件不得带 CR；存量 CRLF 文件看差值不看绝对值 | 编辑器改行尾、批量脚本丢 CRLF |
| p6 | 版本真相（LIVE）≠ 集成头 → 部署漂移 | 并线了没部署、部署了没写版本真相 |
| p7 | 界面路由存活（404 消费） | 菜单在、路由丢 |

## 四、总纲：只验期望方向是所有坑的公因式

两天内的全部误报、漏报、假绿套进同一个模子：**只断言「该发生的发生了」，没断言「不该发生的没发生」**（或反过来）。所以每条判据都配反向断言，每批夹具都造「存量带病、本次无辜」的样本，每次绿都问「它是真查了，还是输入为空所以什么都没查」，每次红都问「靠哪一条抓到的，其余分支是不是从来没命中过」。

## 五、和 CI 的区别

CI 检查代码对不对；轨迹编译检查**流程有没有闭合**：回执到了没登记、登记了没并线、并线了没部署、部署了版本真相没更新、告警发了没人处置。它也审舰长：并线部署是舰长亲手做的，最容易自我放行。

## 六、token 经济

- **实测数字（本机，变更单核对流程）**：编译前每单约 1.2 万 token、分钟级（模型逐步查 SQL/git 再判）；编译成图后**常规单 0 次模型调用、0.6 秒**，48 轮真实运行零静默错误；并线前门禁图 **1.2 秒 / 0 调用**。立项时的止损线是「模型调用/token 降 ≥30%」，实测常规单降 100%，只有异常分支才回到模型。折算：每 100 张常规单省约 120 万 token（按每单 1.2 万计）。**别误解**：值钱的是「确定性图 + 岔路口才调模型」，不是把图编译成二进制——图的解释开销近似为零。


- 机械判点（`type: mechanical`）复放不调用模型：p1/p2/p4/p5/p6/p7 每张单零 token；轮询器每分钟跑也不花钱。
- `type: llm` 的判点只在异常分支进模型，并且只带该分支的上下文（例如 p3 两侧文件集合的差异行），不是整张单的 diff。观测样本：p3 十轮里两轮进模型。
- 对比：让模型每张单都重审，要读完整 diff + 登记 + 回执，token 随文件数线性涨，而且「永远绿」风险更高。
- 判点稳定度是归纳器算出来的，不是人拍的：一个判点连续多轮机械规则与实际判决一致、无反例，才降级为机械；反例出现就升回 `llm`。所以省 token 的边界随数据自动收放。

## 七、接入一个新流程要准备什么

1. 让该流程的每一步产出 `verdict=` 字段（轨迹契约）。
2. 跑 10 轮以上，让归纳器给出判点稳定度。
3. 把稳定判点转机械，其余标 `llm`；为每个判点写一条反向夹具。
4. 挂进轮询器，告警落盘到回执目录，定义自清判据。
